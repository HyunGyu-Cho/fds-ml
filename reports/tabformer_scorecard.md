# 외부 데이터 성적표 — IBM TabFormer로 같은 설계 다시 시험

- 만든 시각: 2026-11-02 15:57 UTC · `python tabformer_scorecard.py`
- 데이터 출처: IBM TabFormer 합성 카드 거래 (https://github.com/IBM/TabFormer, Apache 2.0). IBM이 이 실험을 검토 · 보증한 것은 아님. 데이터는 이 저장소에 넣지 않음
- 변환: `tabformer_convert.py` (고객 단위 표본 · 금액 달러 × 환율 · 환불 제외 · 오류 있으면 거절 · 기기 정보 없음)
- 나누기: 시간순 Train 749,162 · Validation 160,532 · Test 160,537 (경계를 넘는 공격 묶음 1개 제외). 아래 숫자는 모두 Validation
- RF (TabFormer로 학습): rf-v2와 같은 칸 12개 · 같은 설정, 학습 140초, Validation F1 최고 기준값 0.05 (F1 0.0227)
- RF + 지역 칸: 위 RF에 "이 손님이 앞서 같은 장소(가게가 있는 주 · 나라, 온라인은 ONLINE)에서 결제한 적 있나" 한 칸만 더함 (학습 84초). 돈워리의 "평소와 다른 접속 국가"를 대신하는 확인 실험 — 원인이 장소 정보 부족인지 확인
- RF + 국가 A · B (Ⓥ3): 장소를 국가 단위로 바꿔(미국 주 → US, 해외는 나라, 온라인 → 국가 없음) 한 칸만 더함. A "앞서 이 국가에서 결제한 적 있나" · B "앞선 결제에서 가장 많은 국가(동률이면 먼저 나온 국가)와 다른가", 이력 없으면 기본 국가 US와 비교, 국가 없음은 -1 (학습 124초 · 80초)
- rf-v2 (합성 학습 그대로): 팀 ai-server 모델과 같은 파일을 다시 학습하지 않고 채점 — 처음 보는 데이터에서도 통하는지
- Rule: `rule_engine.py` (팀 R01~R08 재현). 기기 · IP · 차단 목록이 없어 R02 · R05 · R07은 꺼짐
- 합성 데이터 결과라 실제 결제 성능의 근거는 아님
